- **Find — SHIPPED** (Explore + Search Build Brief + Revision changeset; as-built in Conventions Addendum 5/6). Explore (browse/push) and Search (retrieve/pull) shipped as **one screen, one rail item** over **one shared in-memory index** — all seven browse databases (Notes, Tasks, Projects, Tags, People, Collections, Resources) paginated fully and fetched in parallel on entry, cached at module scope for the page session; Domains resolved into an id → code/color map only (never its own tab). **Every tab is a Search → Insights → Library dashboard**, not a plain list. **Insights** (revised this pass — "Recently Added" removed everywhere, redundant once the Library is already date-sorted, and refilled with charts): Notes = **Notes by Type** load bar (zero-count Types excluded, schema order) + Top-5-Tags-by-note-count list; Tasks/Projects = **by-Domain load bars** (domain-colored, via project rollup, always all six domains — a single-domain filter just collapses the bar to that one count, no special-casing); Tags = **Top-10 bar chart** (one bar per tag, olive-on-sage — a genuinely distinct chart shape from the load bar, not just a relabel) + Recent Activity; Collections = Top-3-by-member-count list + Recent Activity; Resources = **Resources-by-Type load bar** (falls back to Recent Activity only if the Type field can't be resolved) + Recent Activity; People = Recent Activity only. **Recent Activity is one shared derivation** (Tags/Collections/Resources/People) — whichever Notes/Projects/Tasks actually carry that entity's relation, ranked by most-recent of created/edited, always global (never domain-filtered, cross-cutting). Below that, a flat, dense-row **Library sorted by `created_time` descending on every tab**, each row carrying a date-added and entity-specific pills (Notes: Type(s)+Tags · Tasks: Status+Priority-as-stars+Project · Projects: Status+"N of M done" · Tags: up to 5 recent Note-Types · People: Note-Types+Project; Collections/Resources: base row only). Member counts and every relation-name array behind the pills/Insights/Recent-Activity are tallied once from the already-fetched pages — every DB with its own relation property pointing at Tags/Collections/Resources contributes, same reverse-relation set the Tag/Collection profile's reference shelf already reads — never a per-row query. A Task's domain is the **project rollup**, and a Project's "N of M done" reads the completed-count rollup directly (falling back to `round(progress × total)`) — both resolved locally against the already-fetched Projects, no per-record network call. A domain resolution miss guarantees **no chip**, never a stray literal `"undefined"` (fixed this pass, guarded at both the resolve and the render site). **Domain filter** scopes both Library and Insights on the three domain-bearing tabs; the four cross-cutting tabs keep their full list and (always-global) Insights with a "not domain-scoped" caption. **Search**: a debounced (~180ms) box pinned in the header; typing swaps the body for unified results grouped by entity type, and the *same* tab row becomes scoping chips (click a tab to narrow to its full ranked list; a "Search everything" chip clears back to unified) — ranked exact → prefix → token/substring → fuzzy-title (Levenshtein, threshold scaled to query length) → resolved-relation `metaBlob` match, tiebroken by recency; a `PREFIX-123`-shaped query jumps straight to that record. Search state (`q`/`domain`/`tab`) reflects into the hash via `history.replaceState` (survives refresh, shareable, never re-triggers the router). **Route** `#/find`; `#/explore` and `#/search` alias through. **Ships without body-text search** (Phase 1) — the index's `body` slot exists on every record but stays empty; **Phase 2** (progressive background hydration of Notes bodies, `last_edited_time`-keyed incremental cache, snippet on match — which is also what fills the row's already-structurally-present snippet slot) is documented but not built. *(The Phase 1.5 donut phase originally planned between these two was deleted by the Revision changeset — both chart primitives are bars, not charts-then-donuts.)* Explore's own *evaluative* signal layer (dormancy, on-this-day, drift) stays **deferred to Home** — Find's Insights are deliberately descriptive-only (composition/prominence/freshness), a boundary drawn explicitly so shipping Find doesn't quietly pull Home's scope forward. **Rows are built on the shared rail-less row grid** (Conventions Addendum 6): a right `--railless-gutter` reclaimed on the content column instead of handed wholesale to a rail-less screen's full width, and a two-zone row (flexible content zone + a fixed-width, right-aligned date-added column) so dates stack into one column across every row instead of trailing the panel edge.

## Remaining core screens (Deferred)

- **Compose** — long-form authoring surface. In Capture a blank line delimits separate notes; in long-form it must mean a paragraph break. Compose inverts that and writes a single note with real rich text. Distinct from the Note profile, which *displays* a body — Compose *authors* it. **Absorbs the deferred body-editing scope beyond the edit slice's block ops** (block-type creation/conversion — headings, lists, quotes, callouts — reordering, slash-commands, mid-document insertion). **Watch this one:** Nita does long-form in-app; if it becomes daily, Compose has a case to jump ahead of Home (and possibly closer to Today).
- **Home** — built last; needs a populated system. The "noticing / surface-by-exception" dashboard (drift alerts, on-this-day, pulses), distinct from Today (seeking). **Absorbs Explore's own signal/insights layer** (dormancy, on-this-day, drift), deliberately deferred out of Find (Find Build Brief §0) — the browse/index half of Explore already shipped there. Open: comparison baseline + metric definitions.
- **Find Phase 2 — body-text search.** Notes-first, progressive background hydration (render browse + metadata-search immediately, hydrate bodies in throttled batches after first paint), `last_edited_time`-keyed incremental cache (only a changed note's body re-fetches on rebuild), snippet-on-match, ranked below title/metaBlob matches. Design is already accounted for in Phase 1's index shape (an empty `body` slot on every record) — this is additive, not a rework.
